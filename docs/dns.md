# DNS и Cloudflare

## Что делает сторож в DNS

Только две операции над A-записями **одного** имени (`failover.dns.name`):

- убрать записи с IP мёртвого моста;
- вернуть запись с IP ожившего моста (`ttl` из конфига, `proxied: false`).

Ничего другого в зоне сторож не читает и не меняет. Токен с правом *Edit zone DNS* на одну
зону — достаточный и безопасный объём прав.

## min_pool

`failover.dns.min_pool` — минимум записей, которые должны остаться в пуле. Сторож не
уберёт запись, если после этого записей станет меньше. Для двух мостов `min_pool = 1`:
последний живой мост никогда не будет убран. При «оба мертвы» пул не трогается вовсе
(живых нет — переключать некуда).

## TTL

TTL 60 секунд: клиенты и резолверы перестанут получать мёртвый адрес через минуту после
удаления записи. Больший TTL растягивает переключение, меньший у Cloudflare недоступен.

## Другой DNS-провайдер

В `bridge_guard.py` класс `Cloudflare` реализует четыре метода: `records()`, `remove(ip)`,
`add(ip)` и служебный `zone_id()`. Провайдер с похожим API (любой, где можно перечислить
A-записи имени, удалить и создать одну) добавляется классом того же вида; выбор по
`failover.dns.provider`. Присылайте pull request.
