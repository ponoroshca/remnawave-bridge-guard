# Безопасность: что сторож делает с вашей системой и как всё отменить

Написано для тех, у кого уже работает панель, боты и ноды, и кто хочет знать заранее,
что именно изменится и как это вернуть.

## На сервере сторожа

Установка пишет только сюда:

| путь | что там |
|---|---|
| `/opt/bridge-guard/` | скрипты и бинарник Xray-core |
| `/etc/bridge-guard/` | `config.json` (права 600), токен Cloudflare (600) |
| `/var/lib/bridge-guard/` | состояние, бэкапы хостов панели |
| `/usr/local/bin/bridge-guard`, `lanes-probe`, `exit-probe-conf`, `install-exit-probe`, `refresh-exit-probes` | ссылки на скрипты |
| `/etc/systemd/system/bridge-guard.service`, `.timer` | юниты |

Перед записью установщик проверяет, что этих имён не занимает что-то чужое: если
`bridge-guard.service` или `/usr/local/bin/bridge-guard` уже есть и это не наши файлы —
он останавливается, ничего не тронув. Ваши nginx, docker, боты, панель, другие таймеры
не затрагиваются. Пакеты ставятся только `curl`, `unzip`, `tar`, если их нет.

Проба поднимает xray на локальных портах от `3140` (только `127.0.0.1`); занятые порты
пропускаются. Прогон — один раз в минуту, несколько секунд, с жёстким пределом 150 с.

Снять всё: `sudo /opt/bridge-guard/uninstall.sh` (конфиг и состояние спросит отдельно).

## В панели Remnawave

Мастер (один раз):
- **создаёт одного пользователя** (`bridge-probe`: без лимита трафика, срок 10 лет) и
  добавляет его в сквады инбаундов, через которые ходят клиенты; существующему
  пользователю с этим именем — только дописывает недостающие сквады;
- по вашему явному «да» — **создаёт хост подписки** на имя DNS-пула (если такого хоста
  нет). По умолчанию — нет.

Сторож (при отказе моста):
- **меняет поле `address` у хостов подписки** с адресом пула или мёртвого моста на IP
  живого; перед каждой правкой сохраняет полный список хостов в
  `/var/lib/bridge-guard/backups/hosts.<время>.json` и запоминает исходный адрес каждого
  хоста, чтобы вернуть его.

Ничего другого в панели не меняется: ни профили, ни ноды, ни сквады, ни пользователи.
Ключи Reality читаются, но никуда не передаются и не записываются, кроме конфига сторожа.

## В DNS (Cloudflare)

Только A-записи **одного** имени (`failover.dns.name`): убрать запись мёртвого моста,
вернуть запись ожившего, по вашему «да» в мастере — создать записи для мостов. Токен с
правом *Edit zone DNS* на одну зону — больше прав не нужно. Сторож никогда не оставит
в пуле меньше `min_pool` записей.

## В Telegram

Только отправка сообщений указанному чату. Определение получателя в мастере читает
входящие сообщения нового бота (getUpdates) один раз, во время настройки.

## Как отменить любое действие

| что случилось | команда |
|---|---|
| сторож перевёл хосты / убрал запись, а мост на самом деле жив | `bridge-guard rollback` — хосты на исходные адреса, A-записи всех мостов обратно, счётчики сброшены |
| ошиблись в настройке | `bridge-guard setup` — прошлые ответы предложены по умолчанию; старый конфиг сохраняется рядом (`config.json.bak-<время>`) |
| хотите остановить сторож, ничего не удаляя | `systemctl disable --now bridge-guard.timer` |
| хотите вернуть хосты из конкретного бэкапа | файл `hosts.<время>.json` — поле `address` каждого хоста; вернуть через панель или `PATCH /api/hosts` |
| снести всё | `sudo /opt/bridge-guard/uninstall.sh` |

Все переключения сторожа — это ровно две обратимые операции: адрес хоста и A-запись.
Профили, ноды и клиентские ключи он не трогает, поэтому «сломать сеть» ему нечем.
