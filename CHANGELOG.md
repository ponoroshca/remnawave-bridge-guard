# Changelog

## 1.3.1 — 2026-09

- Панель недоступна — мосты проверяются по списку прошлого прогона, а не пропускаются.
- DNS: сторож помнит, какие A-записи убрал он сам, и возвращает только их (`rollback` — «как было»).
- `install-exit-probe` не затирает чужой `exit-probe.service` на мосту; `SSH_PORT` для нестандартного ssh.
- Ctrl+C в мастере — аккуратный выход; `--yes` без получателя Telegram — честное отключение, а не ожидание ввода.
- Документация сверена с кодом: примеры экрана в START-HERE — точные строки мастера.

## 1.3.0 — 2026-09

Для тех, кто ставит впервые, и для тех, кто боится за работающее:

- **Одна команда**: установщик после установки сам открывает мастер (в терминале);
  `NO_SETUP=1` — только установить.
- **Не затирает чужое**: если `bridge-guard.service` или `/usr/local/bin/bridge-guard`
  уже принадлежат другой программе — останавливается, ничего не изменив.
- Мастер: у каждого вопроса — где взять ответ (панель, @BotFather, Cloudflare);
  **получателя Telegram определяет сам** (нажмите Start у нового бота), распознаёт «этот бот
  уже занят другой программой»; предупреждает, если сторож ставят на панель или на мост;
  предлагает **создать A-записи** мостов в DNS-пуле и хост подписки на имя пула (по «да»);
  в конце присылает репетицию отказа как **тестовую тревогу** с пометкой 🧪.
- Пробы используют только свободные локальные порты; у прогона жёсткий предел времени.
- Документы: [START-HERE](docs/START-HERE.md) — по кликам с нуля, с примером экрана и
  таблицей «вы видите → что сделать»; [SAFETY](docs/SAFETY.md) — что меняется на сервере,
  в панели, в DNS и в Telegram и как отменить каждое действие.


## 1.2.0 — 2026-09

Под чужие ноды, а не только под одну схему:

- Параметры клиента собираются **для каждого моста из его собственного профиля** — как
  ссылка подписки: Reality / TLS / без шифрования; TCP, WebSocket, gRPC, xHTTP, HTTPUpgrade;
  `sni`, отпечаток и путь — из хоста подписки; ключ Reality считается из приватного.
- `bridges: "auto"` теперь по `auto.profiles` (все ноды этих профилей) или `auto.countries`;
  в явном списке у моста может быть `profile` (параметры из панели) или `probe` (руками).
- Мастер показывает все ноды панели с профилем и страной, предлагает мосты по умолчанию,
  выбор запоминает как профили → страны → явный список; служебного пользователя кладёт
  в сквады всех нужных инбаундов (существующему — добавляет недостающие).
- `doctor` показывает параметры пробы по каждому мосту и проверяет сквады по каждому инбаунду.
- `lanes-probe --bridge <имя|IP>` — профиль моста берётся из панели; показывает тип
  каждого режима (reality/tcp, tls/ws …). `exit-probe-conf --bridge`, `install-exit-probe`
  без аргумента профиля.


## 1.1.0 — 2026-09

«Поставил и забыл»:

- `bridge-guard setup` — мастер: находит профиль и мосты в панели, инбаунд и ключи Reality,
  заводит служебного пользователя в нужном сквадe, находит DNS-пул, проверяет токен
  Cloudflare и Telegram (тестовое сообщение, подбор прокси), пишет конфиг с бэкапом старого,
  прогоняет пробу через каждый мост, показывает репетицию отказа, включает таймер.
  Все ответы можно передать флагами, `--yes` — без вопросов.
- `bridge-guard doctor` — чек-лист с подсказками: конфиг и права, xray, панель и токен,
  служебный пользователь и его сквады, DNS-токен и состав пула, Telegram, проба через
  каждый мост, таймер и последний прогон, заморозка.
- `bridge-guard rollback` — вернуть хосты на исходные адреса и A-записи всех мостов,
  сбросить состояние; `--dry-run`.
- `bridge-guard status` показывает последние события.
- `bridges: "auto"` — мосты берутся из нод профиля каждый прогон.
- Хосты: `match_addresses` (список), исходные адреса запоминаются и возвращаются; при
  смерти второго моста хосты уезжают дальше без потери исходных адресов.
- Сердцебиение: `heartbeat.url` после каждого прогона и суточная сводка в Telegram.
- Установка одной строкой (`curl … | sudo bash`), `uninstall.sh`, `refresh-exit-probes`
  для всех мостов из панели, `install-exit-probe` работает из `/opt/bridge-guard`.
- Валидация формата `uuid`/`public_key`/`short_id` — с заглушками из примера сторож не запустится.

## 1.0.0 — 2026-09

Первый публичный выпуск.

- bridge-guard: проба каждого моста настоящим xray-клиентом (VLESS + Reality → внешний IP),
  гистерезис `fail_n`/`ok_n`, заморозка при `max_dead`, два режима переключения — DNS-пул
  (Cloudflare, `min_pool`) и хосты подписки панели, бэкап хостов перед правкой,
  Telegram с прокси, `--dry-run`, `--fake-dead`, `--status`.
- exit-probe: TCP-достижимость выходных нод с моста + контрольные точки
  «отрезан мост / нет сети / проблема ноды», подавление повторов.
- lanes-probe: все режимы подписки через мост как клиент — IP выхода, отклик, скорость.
- Установщики для хоста сторожа и для мостов, юниты systemd, документация.
